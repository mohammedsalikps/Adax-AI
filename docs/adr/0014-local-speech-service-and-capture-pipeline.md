# ADR 0014: A local speech service behind a provider boundary, and the capture pipeline (raw → extracted → doctor-confirmed)

- **Status:** accepted and implemented in slice V2 ([DOCTOR_APP_PLAN.md](../DOCTOR_APP_PLAN.md), [STATUS.md](../STATUS.md)). It carries out the speech-to-text and important-point-extraction parts of [ADR 0012](0012-local-first-ai-hosted-providers-opt-in.md); the rest of that ADR (a registry for language-model chat providers, and "a key alone enables nothing" for them) is **not** built yet and stays planned for V3.
- **Date:** 3 Oct 2026

## Context

Before V2, speech-to-text meant a hosted OpenAI-compatible endpoint that switched itself on when `AI_STT_API_KEY` was present, so consultation audio could leave the machine because a key was set. Audio cannot be pseudonymised. The owner's direction (ADR 0012) is that the core AI must not depend on a hosted API and that consultation audio must never go to a third party by default. V2 has to make live consultation capture work for real: consent, microphone, local speech-to-text, timestamps, language, speaker labels set by the doctor, important-point extraction, and a clear line between what was heard, what the system proposes and what the doctor confirmed.

## Decisions

1. **A dedicated local speech service, not an OpenAI-compatible server.** `services/speech` is a small FastAPI program around [faster-whisper](https://github.com/SYSTRAN/faster-whisper) (CTranslate2 runtime, MIT) with model `Systran/faster-whisper-small` (MIT), CPU, int8. It listens on `127.0.0.1:8002` only. Its protocol (`GET /health`, `POST /v1/transcribe`) is our own and says what we need to know: segment times from the audio, the language the model detected and how it got it, a model score per segment *labelled for what it is* (`mean_token_probability`, not a calibrated chance of being right), the model and runtime identity and the SHA-256 of the weights file, and `speakers: not_identified`. We chose not to imitate a hosted API's shape: a client that speaks it would also speak to the hosted original by changing one URL.
2. **The API side is a `Transcriber` interface with exactly one implementation, `LocalSpeechTranscriber`.** The provider setting has two values, `none` (the default) and `local`. There is **no hosted adapter in the code**; the old one was removed, and `AI_STT_API_KEY` is ignored (with a start-up warning if it is set). There is no fallback: if the local service is down the screen says "Local transcription unavailable" with the reason, recording is not offered, and typed transcripts keep working.
3. **Loopback is enforced twice.** The configured URL must name `127.0.0.1`, `[::1]` or `localhost` (a strict allow-list: other forms of the loopback range, IPv4-mapped IPv6 addresses and user-info tricks are refused) unless the operator sets `SPEECH_ALLOW_NON_LOOPBACK`, which is a deliberate act and not a default; the launcher refuses a non-loopback `SPEECH_HOST` in the same way. Requests are sent with `redirect: 'error'`, so a service that answers by redirecting the audio somewhere else is a failure. The service itself answers only requests whose `Host` is a loopback name (a web page cannot reach it by rebinding a DNS name it controls), asks for a client header (`x-adaxai-local`) that a browser cannot send to another origin without a pre-flight the service never answers (it has no CORS support), and serves no documentation or schema routes. These two checks were described in the first draft of this ADR but **not wired in** until the pre-commit security review found it; they are now middleware with tests that forge the `Host` header and omit the header. The service has **no sign-in**: any process on this computer can use it.
4. **The service keeps nothing.** Audio is decoded from memory: the multipart parser is told to keep uploads in memory (it would otherwise spool anything over 1 MiB to a temporary file, which the review also found), and the engine never writes audio itself. It logs class names only: a log filter replaces the message and traceback that the web server would otherwise log for an unhandled error (which could hold request data). The launcher gives the Python process an allow-listed environment (not the database passwords or provider keys that `.env` holds). The model is loaded from a directory with the hub set offline at inference time; the one-time download (`npm run speech:model`, owner-approved, ~486 MB) verifies the files against `services/speech/models.lock.json`, and **the weights are checked against the pinned SHA-256 at every load** (a file that does not match is not loaded).
5. **The task is always "transcribe".** The model's translate mode is never used, so the stored text is in the language that was spoken. Language is detected per request (or taken from an operator hint) and stored with each segment and each part, with its source (`detected` or `hint`).
6. **Timestamps are on the recording's own timeline.** The browser records in parts (20 s by default, restarting the recorder so every part is a complete file), and sends each part with its offset on the recording (recorded time only: a pause adds nothing). A segment's stored start and end are the part's offset plus the model's time inside the part, clamped to the part's decoded length plus two seconds of slack. A part may not start before the part that precedes it. The offset is checked against the wall-clock time since the recording was opened (plus a small slack). A part's duration comes from the decoded audio, not from the client.
7. **Segments are append-only; the speaker is a separate, append-only review.** The model identifies no speakers, so a transcribed line starts with no speaker. The doctor assigns Doctor, Patient, Nurse, Relative, Attendant or Other, line by line; each assignment is a new row in `transcript_segment_speakers`, and the latest one is the reviewed speaker (Unknown clears it). The words never change. A fact extracted before a speaker was corrected is flagged `speakerChanged` so it is not trusted silently.
8. **Extraction defaults to fixed rules on this computer** (`extract-rules-v1`: lexicons, clause splitting, negation and hedge scope, durations, number words; English only; facts are the speaker's own words, never paraphrased). Rules, not a model, because a small local language model that returns schema-valid JSON reliably could not be shown on this hardware in this slice, and rules can be inspected, versioned and measured. A hosted language-model extractor exists only if `ai.extraction.provider: llm` is set on purpose, and every run records that it was external. Lines in another language are skipped and counted, and the screen says so.
9. **Three visibly different kinds of content, and nothing moves between them without the doctor.**
   - **Raw transcript:** what the model heard (neutral card, a rule down the left edge, time and speaker on each line, "Low model score" where the model itself was unsure).
   - **Extracted draft:** what the rules propose, each with its category, the transcript lines it came from (shown with their times and clickable), the rules version and the time it was made (dashed violet card, "Extracted draft").
   - **Doctor confirmed / rejected:** only through an explicit action (green "Doctor confirmed"; rejected points are struck through and kept). A point whose speaker nobody assigned, or that conflicts with the record, needs an explicit tick first (the server enforces this, not only the screen).
   - **Confirming never writes to the note.** "Add to note" is a separate recorded insertion with provenance. `listConfirmedPoints` is the single read of confirmed points that the later summary slice will use as input; it returns nothing that was not confirmed.
10. **Consent is checked on every step that handles audio, not only at the start.** Starting a recording, every part (before its body is read, again before it is stored, and again after the speech model returns, so nothing is stored for a part that was transcribed after a withdrawal), every upload and every retry re-check the patient's recording consent, and the visit must still be with the doctor. The reason a recording ended is derived from the consent, not accepted from the browser. If it is withdrawn the live recording is ended with the reason `consent_withdrawn`, the browser (which also polls) stops the microphone and discards the part it was recording, and the server refuses further parts. The consent *wording* and versioning are unchanged from slice 2 apart from stating that audio stays on this computer; **that wording change needs a legal and clinical-governance review before any real use**.
11. **One live recording per consultation**, enforced by a partial unique index; a second start is refused, except that a recording whose last activity is old is ended as stale and replaced.
12. **Provenance on every run:** provider, model, runtime, compute type, weights SHA-256, **local or external**, prompt or rules version, input/output hashes, and the settings snapshot (extending ADR 0012 item 5).

> **Update (V2.1, [ADR 0015](0015-hosted-ai-egress-policy-and-speech-service-hardening.md)):** several items listed below as left open were closed afterwards: hosted transcript-text egress (now off by default, a key alone enables nothing), content sniffing and a duration bound before decoding, the demuxer choice, rate limits, the migration 0025 pre-flight and remedy, and withdrawal ending live recordings in its own step. What remains is classified in ADR 0015 §4.

## What the pre-commit security review changed, and what it left open

An independent adversarial review (read-only, of the whole slice) reported 22 findings; the confirmed ones were fixed with regression tests: a sentence cut at a part boundary lost its negation (parts are now stitched when a line ends mid-sentence, and any line still cut is flagged); consent withdrawn during transcription still stored the part's text; a paused visit did not stop capture; jobs could be left "running" forever (preconditions and storage errors now fail the job, and interrupted jobs are failed at start-up); stale speaker attributions could be confirmed silently (now a server-enforced tick); re-extraction brought back rejected points; very long unpunctuated input could stall the process (the lookback is windowed and lines are capped); the service's Host and header checks, spooling and log claims were not true (now are); the launcher leaked secrets to the Python process (allow-listed); consultation audio was playable by nurses (doctor only); database errors could log the stored text (serializer); migration 0025 creates a unique index that fails (atomically, nothing half-applied) on a database where an encounter already has several recordings left `live` by the V1 code. It was not edited after being applied here (the migration runner refuses that); instead the clean-up is a **documented pre-step** for any such database: `UPDATE transcripts SET status = 'final' WHERE status = 'live' AND id NOT IN (SELECT DISTINCT ON (encounter_id) id FROM transcripts WHERE status = 'live' ORDER BY encounter_id, created_at DESC)` before running `npm run migrate` (the end-reason column does not exist yet at that point). The development, test and end-to-end databases here had none.

**Left open, on purpose, and recorded in the [risk register](../safety/RISK_REGISTER.md):**

- **Transcript text can still go to a hosted service from the drafting and recommendation steps** when `ANTHROPIC_API_KEY` is set (after consent, by a click; audio never does). The screen now says so, but "a key alone enables nothing" for the language-model path (ADR 0012 items 1 and 3) is the first thing for V3.
- No content sniffing or decoded-duration cap before PyAV/FFmpeg decodes uploaded audio; no sign-in on the service.
- No rate limits or quotas on the expensive endpoints beyond size limits and a bounded part number.
- A part lost after the browser's four retries is a transient warning; after a reload the transcript does not mark the gap. A very long upload (hours) can time out at 180 s and is reported as such; the segment cap is 5,000 lines.
- A live transcript left `live` by an abandoned recorder is not ended by signing or discarding the consultation (the recorder itself stops on those answers).
- Captured audio and text are not purged when consent is withdrawn; discarded consultations keep their audio; audio is not encrypted at rest. These need an owner decision.

## Consequences

- **A download is needed once** (the PyPI packages, ~70 MB, and the model, ~486 MB), approved by the owner. Without it the app says transcription is unavailable and everything else works.
- **Quality is measured on synthetic speech only** (see [safety/AI_MODELS.md](../safety/AI_MODELS.md)): clean text-to-speech audio, English only, one annotator. Real clinic audio, accents, noise, children, overlapping speech and non-English languages are **not** evaluated. The speech model is multilingual in principle; **the application supports English only** because that is all that could be measured, and the extractor reads English only.
- **CPU speed is the limit:** a part is transcribed after it is recorded, not word by word, so the transcript appears in 20-second steps with a delay.
- **Real, not mocked, where it matters:** the model was run on this machine; the browser→API→service path is covered by end-to-end tests that use a labelled test stand-in for the service (so the suite needs no model); the real model's behaviour is covered by the evaluation and by the service's own optional real-model test.
- **Not solved:** speaker identification (the doctor assigns), real-time word-by-word streaming, translation (never silent), pseudonymisation of audio (not needed while nothing leaves the machine), retention limits (audio is kept with the consultation under the existing file rules; there is still no retention schedule), and clinical validation of any output.
