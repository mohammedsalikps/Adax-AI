# AI and device status: what is actually real

**Verified 3 Oct 2026 by reading the code (not the documents) and by the tests named below; capabilities A and B and the data-flow sections were rewritten on 4 Oct 2026 for slice V2.** This page says what runs, what needs an external service or credential, what is only exercised by a test double, and what does not exist. It is deliberately conservative: an endpoint existing is not "working". Nothing here is a claim of clinical validity, diagnostic accuracy, regulatory approval or production readiness. The audit with line-level evidence is in [DOCTOR_APP_AUDIT.md](DOCTOR_APP_AUDIT.md); the target architecture is [ADR 0012](adr/0012-local-first-ai-hosted-providers-opt-in.md).

## Words used

| Word | Meaning |
| --- | --- |
| **Real** | Runs on this machine with no external service, and is covered by automated tests |
| **Needs a hosted provider** | The code is real but does nothing without a key for an external service (and then sends data there, after consent) |
| **Test-only** | Exercised only against a test double or a local mock of the external service; never run against the real thing, so its quality with a real model is **unknown** |
| **Simulated** | Stands in for something that does not exist yet, and is labelled so |
| **Unavailable** | Shown to the doctor as "not available" with the reason |
| **Absent** | Does not exist |

## The eight capabilities

| Capability | Status | What actually runs | Needs an external credential? | Tested how |
| --- | --- | --- | --- | --- |
| **A. Voice transcription** | **Real, local; measured on synthetic speech only** | **Consent check; browser microphone recording (start, pause, resume, stop) in 20-second parts; transcription by a speech model that runs on this computer** (`services/speech`, `faster-whisper` `small`, CPU, int8, loopback only): each part is transcribed after it is recorded; **timestamps on the recording's own timeline, language per line (with how it was decided), a model score per line (labelled as a model score), the model, runtime and weights SHA-256 on every run**; audio upload and storage; typed or pasted transcript. **No hosted speech provider exists in the code** and there is no fallback: without the local service the screen says "Local transcription unavailable". **No model identifies speakers**: the doctor assigns them, line by line (append-only review). ## What leaves this machine, and when

- With **nothing configured, nothing is sent.** The test configuration never carries provider keys, and tests never call a real provider.
- **Consultation audio never leaves this computer.** Speech-to-text is local only: the hosted adapter was removed, `AI_STT_API_KEY` is ignored (with a start-up warning), the speech URL must be loopback, redirects are refused, and a down service means "Local transcription unavailable", never a fallback. Important points are found by local rules.
- **Transcript *text* can still leave this machine from the language-model steps.** This development machine's `.env` still holds an Anthropic key, so "Generate draft" and AI recommendations (and photo description) send consultation text (the patient's registered name, MRN and phone number are replaced; the scrubbing is best-effort) to Anthropic **after the patient's consent, when the doctor clicks**. The assistant panel now says so on screen. "A key alone enables nothing" for this path is **not built** (it is the first item for V3). The old hosted speech key in `.env` (`AI_STT_API_KEY`) is now ignored; removing both keys is the owner's decision.
- Each use is gated by a recorded consent (`ai_recording`, `ai_record_assistant`, `ai_image_analysis`) and audited with the model, prompt version and input and output hashes.
- **Built (ADR 0014):** the local speech boundary and the local extractor. **Still planned (ADR 0012, not built):** the provider registry for language-model chat with a default of `none`, a **local, open-weight** chat model, hosted providers only by explicit choice. This machine has an RTX 2050 (4 GB), 15.7 GB of RAM; the speech model runs on the CPU.

## Raw, extracted and confirmed

| Stage | Where | Rule |
| --- | --- | --- |
| **Raw transcript** | `transcript_segments` (+ `transcript_chunks`, `transcript_segment_speakers`) | Append-only; text exactly as heard, never translated; times, language, model score and run on each line; the speaker is **never** set by the model: it comes from a typed "Doctor:" / "Patient:" prefix (typed text) or from the doctor's assignment (append-only review) |
| **Extracted draft** | `clinical_facts` (important points), `ai_draft_items`, recommendations | Always *pending*, always marked as extracted/AI with the rules or model version and whether it ran locally, never part of the record; a fact is carried forward when the doctor re-runs extraction (confirmed ones are not duplicated, rejected ones do not return) |
| **Doctor-confirmed** | accepted or edited item (shown as *Doctor confirmed*), then a recorded insertion into the note | Confirming does **not** write to the note: only `POST /encounters/:id/insertions` ("Add to note"), with provenance; flagged items need an explicit confirmation; **nothing AI-produced is signed or inserted without the doctor**. `listConfirmedPoints` is the only read the later summary will use |

A known looseness: accepting a *note-draft* item inserts it into the note draft in one click (a *facts* item needs a second click). The doctor still signs.

## What slice V2 changed here

It made capability A real and local and capability B local and rule-based, added the raw / extracted / confirmed separation to the consultation screen, and removed the hosted speech path. It did **not** build the consultation summary (D), full Mana (F), device or thermal models, or any language-model change; drafting, recommendations and image description are as before (keyed, external, after consent) except that the screen now discloses that text goes to an external service. Everything above was verified against the code and the tests named in [STATUS.md](STATUS.md) on 4 Oct 2026; nothing here is clinical validation.

### Earlier (slice V1)

Nothing in the AI itself: it added the deterministic patient context (C) and the patient summary, and removed no safeguard.
