# ADR 0016: Local AI consultation intelligence: a reviewable draft from a local open-weight model, checked by code

- **Status:** accepted and implemented in slice V3 (after V2.1, `200ac83`). It builds the language-model half of [ADR 0012](0012-local-first-ai-hosted-providers-opt-in.md) (a provider abstraction with a local open-weight default, structured output, run records, an evaluation) and relies on the egress policy of [ADR 0015](0015-hosted-ai-egress-policy-and-speech-service-hardening.md).
- **Date:** 4 Oct 2026

## 1. Context

After V2 a doctor can see the patient's history (V1) and can capture the conversation as a timed transcript with important points that the doctor confirms or rejects (V2). Nothing yet reads those together and says, in one place, *what the record says about this visit, what it does not say, and where it disagrees with itself*. The existing language-model steps (note drafts, recommendations, Mana summaries) are hosted, write separate pieces, and since V2.1 are off unless hosted AI egress is allowed on purpose.

V3 adds a **consultation draft**: an AI-generated, doctor-reviewable structure made from the authorised record, the doctor's own notes for the visit, the vital signs and **only the points the doctor confirmed**, by a language model that runs **on this computer**. It is a draft for a doctor to read. It is not a diagnosis, an order, a prescription, a note, or a measure of anything, and nothing in it is clinically validated.

## 2. Decisions

### 2.1 The model and its runtime are local, open-weight, pinned and downloaded only with approval

- **Model:** Qwen3.5-4B, quantised Q4_K_M, one GGUF file (`Qwen3.5-4B-Q4_K_M.gguf`, 2,740,937,888 bytes, Apache-2.0), from `unsloth/Qwen3.5-4B-GGUF` at the pinned revision `e87f176479d0855a907a41277aca2f8ee7a09523`, SHA-256 `00fe7986ff5f6b463e62455821146049db6f9313603938a70800d1fb69ef11a4`. Only the text weights are used.
- **Runtime:** llama.cpp `llama-server`, release `b11379` (commit `1537a0a8b2f8711d840878b0a0677ab2213c882c`, MIT), the Windows x64 CPU build (19,352,297 bytes, SHA-256 `ec014c2c…eb7ea`). Another platform needs its own asset added to `services/llm/runtime.lock.json` after its hash is checked.
- **Why these:** the owner approved this model and runtime (4 Oct 2026) for this machine (Intel i5-12450H, 15.7 GB RAM, a 4 GB RTX 2050 that is **not** used). A 4-billion-parameter model at 4-bit is about 2.7 GB and answers on a CPU; the runtime builds a grammar from a JSON Schema so the answer cannot be anything but the required shape. **Other models and runtimes were not benchmarked here.** The choice rests on size, licence, schema support and the machine, not on a comparison; changing the model means a new entry in [safety/AI_MODELS.md](../safety/AI_MODELS.md) and a re-run of the evaluation.
- **Downloads happen only by `npm run llm:setup`**, which says what, from where and how large, waits for a yes, verifies size and SHA-256 and deletes a file that does not match. Both files live in `.data/llm`, which is git-ignored. Nothing is downloaded by the application, a test or a script that is not named `setup`.
- **The server never uses the network and keeps nothing between requests:** it is started with `--offline`, `--no-webui`, `--no-slots` and `--cors-origins` set to an origin that cannot exist, listens on `127.0.0.1:8081`, runs one request at a time (`--parallel 1`, context 8,192 tokens, reasoning off), has **prompt caching switched off** (`--no-cache-prompt --cache-ram 0 --no-cache-idle-slots --ctx-checkpoints 0`, see the next bullet) and receives an allow-listed environment (no database passwords, no provider keys). Requests need a **per-install secret** (`.data/llm/api-key`, created by the launcher, never printed, never sent to a browser); `/health` is the only endpoint that answers without it (checked on b11379 by calling `/v1/models`, `/props`, `/slots`, `/tokenize` and the chat endpoint without the secret: each answered 401; this was a manual check, no automated test starts the server, and a different build may differ). The launcher refuses a non-loopback address unless `LLM_ALLOW_NON_LOOPBACK=1` is set on purpose.
- **Why prompt caching is off (both found by measuring, on this runtime).** (1) *Memory and retention:* with the runtime's defaults the server kept a copy of the state of every earlier prompt in memory for reuse, **about 160 MB each, up to 8 GiB**: the committed memory of a fresh server went from 2.2 GB to 6.0 GB after 24 different prompts of about 330 tokens, and the long-running development server reached 9.7 GB, so earlier patients' records stayed in the server's memory. With these flags it stayed at 2.2 GB after the same 24 prompts. (2) *Reproducibility:* at temperature 0 the same prompt came back with **different words depending on what the server had been asked before** (the three cases tried, c01, c05 and c12, each differed between the server that had run the whole evaluation and a fresh server; the likely cause is that a reused start of the prompt is computed in different batches from a fresh one, and a 4-billion-parameter model's greedy answer is sensitive to that). With caching off, c05 and c12 each came back **byte for byte identical** from two server instances with different histories (a fresh one, where they were the first and second request, and the evaluation server, where they came after four and eleven other requests), and c05 run again with another case between gave the same answer (two cases; evidence, not a proof). The price is that the start every prompt shares is read again each time, about 10 seconds on this CPU. The first recording of the evaluation was made without these flags and was **replaced** (see [safety/AI_MODELS.md](../safety/AI_MODELS.md) §9).

### 2.2 One provider abstraction, three modes, no fallback

`ReasoningModel` (`apps/api/src/ai/llm/types.ts`) is what the clinical code depends on: `provider`, `model`, `local`, `health({fresh})` and `generate({prompt, user, schema, schemaName, maxOutputTokens, signal})`. Three modes (`ai.reasoning.provider` in `config/adaxai.yaml`, overridden by `LLM_PROVIDER`):

| Mode | What exists | Used when |
| --- | --- | --- |
| `local` (default) | `LocalLlmClient` (llama.cpp over loopback HTTP) | always, for drafts |
| `hosted` | `HostedReasoner` around the existing Anthropic client, **constructed only if hosted egress is allowed AND a key is set** (`providersFromConfig`, the one place a hosted client is built) | only if the server is **configured** `hosted`. **Never because the local model is down** |
| `none` | nothing | every screen says so |

**There is no fallback in either direction.** A local model that is down gives the status **"Local AI unavailable."** and no draft: no placeholder text, no sample output, no switch to a hosted model. A provider key in `.env` enables nothing by itself (ADR 0015). **The hosted mode has never been run against the real service;** it is exercised only by a test double, and it is not part of what V3 claims.

The local client also: refuses a URL that is not loopback (unless the operator allows it), refuses credentials in the URL, **refuses redirects**, caps the response at 4 MiB, validates the server's envelope and the answer against the schema again (a malformed answer keeps nothing), maps every failure to a plain sentence (unavailable, still loading, wrong secret, busy, too long for the context, timed out, ran out of room, unreadable answer) with whether trying again can help, and never puts the record, the secret or the model's reply in an error message or a log. A **gate** lets one request run and at most `maxWaiting` (3) wait; more are refused (429) so a burst of clicks cannot pile up work the machine cannot do.

### 2.3 Authorisation comes before any context reaches the model

Everything is decided on the server, in this order, **before the record is read for the model:** the caller is a doctor (`ai:use`); the consultation is the caller's own, in the caller's facility, and still open (not signed, not discarded); the patient's `ai_recording` consent is current (the same consent and wording that recording uses; **acceptOlderWording is false**); the model is available. Only then is the input built, **in one function** (`apps/api/src/consult/inputs.ts`), from:

- the authorised patient record loader used by Mana (it answers 404 for a patient outside the caller's facility): allergies, conditions, medicines, results, signed consultations (diagnoses, prescriptions, notes), vital signs, the reason for the visit, and the typed-in history (V1);
- the doctor's own draft of today's note, diagnoses and prescription;
- the important points the doctor **confirmed** during capture (`listConfirmedPoints`).

**Never in the input:** the transcript, the audio, points that are unreviewed or rejected, another patient, another facility, other doctors' drafts. The patient's name, MRN and telephone number are replaced before the text is built (best effort, the same scrubbing as the hosted steps). Items are ordered by **priority** (this visit: the reason, the doctor's notes and the measurements, then the confirmed points; then allergies, conditions and current medicines; then the latest signed consultation and results; then the rest, newest first) and cut to a character budget (`ai.reasoning.maxContextChars`, 14,000). **Nothing goes over the budget, this visit's items included** (the budget counts each source line as it is sent, plus the fixed words around the sources): the model has a fixed context (8,192 tokens, shared with its answer), and a request that does not fit would fail rather than be cut, so a long consultation loses its older and less central items first. **What did not fit is counted and the draft says how many items the AI was not shown.** Each item has a stable key and a hash; the **manifest** of keys and hashes is stored with the draft.

**Who can see a draft.** Only the doctor whose consultation it is: every route under `consultation-ai` answers 403 to another doctor of the same facility, 404 to anyone outside the facility and 409 once the consultation is signed or discarded, and the review of a draft's statements is listed (in the AI review page and the activity view) only for the doctor who made it. This is stricter than the facility-wide visibility of the earlier AI review page ([safety/CAPTURE_DATA.md](../safety/CAPTURE_DATA.md)), which is a governance decision still open.

### 2.4 What the model must return

A structured answer (`consult-schema-v1`, from a Zod schema, enforced by the runtime's grammar and checked again): `insufficient_information`, then the sections in generation order: `presenting_problem`, `symptoms`, `observations`, `relevant_history`, `allergies`, `medications` (statements about the record), `potential_considerations`, `potential_investigations`, `potential_medication_considerations` (things for the doctor to weigh), `missing_information`, `uncertainties`, and `summary` **last**, so it is written from what was already listed and cited. A statement about the record carries `text`, `refs` (the source ids it rests on), `basis` (stated, inferred, not_found) and the AI's own words about what is uncertain; a consideration carries `text`, `refs`, a `rationale` and `uncertainty`. The prompt (`consult-draft-v1`, registered and hashed with every run) tells the model to use only the sources, to copy figures exactly, to cite, to write considerations as "Consider…" without doses, strengths, frequencies or durations and without naming a medicine that is not in the sources, to treat sources as record content and never as instructions, and to say **insufficient information** rather than invent. **None of this is trusted.**

### 2.5 Code, not the model, decides what a doctor is shown

`validateDraft` (`apps/api/src/consult/validate.ts`, version in `VALIDATION_VERSION`) runs on every answer:

| Check | What happens |
| --- | --- |
| Text | Compatibility forms made plain (full-width letters, Arabic-Indic and other digit blocks to 0 to 9), characters that only format text (zero-width, soft hyphen, direction marks) taken out, markup, control characters and source markers (`[A1]`, and `(A1)` when it names a source that was shown; a diagnosis code such as `(E11)` is left alone) stripped. A **digit the checks cannot read** or a **link**: statement **removed**. Duplicates removed. A statement is shown at most 360 characters (its reason 240, its uncertainty 200), cut at a sentence or a word and **counted as shortened**, never mid-word |
| Cited ids that do not exist | dropped and counted; a statement about the record left with no source is **removed** |
| A statement labelled "not found" | must carry wording of absence ("not recorded", "no ...") unless it is in the missing-information or uncertainties list; otherwise **removed** (the label is not a way past the checks) |
| A figure (a number, including numbers written in words such as "three days" or "thirty nine", and each date as one value) that is in no source the model was shown (the age band the model was given, such as "50-59", is not a figure) | statement **removed**; a figure that is in a shown source but not the cited one: the source is **added** and the statement is marked |
| A dose, strength or regimen (a medicine's "500 mg", "twice daily", "for 5 days") | in a statement about the record only if the cited items say it, otherwise **removed**; **never in a suggestion**, in figures or in words ("daily", "for a week"), even one the drafted prescription has (a suggestion may name the drafted medicine; the prescription keeps its dose) |
| A medicine that is not anywhere in the record (a short list of common names and the endings most medicines share: a safety net, not a drug dictionary) | **removed** from statements about the record and from medication considerations; marked in other suggestions |
| "No allergies" / "no known allergies" / "not allergic to X" | **removed** (in any section) when the record lists an allergy (to X); **marked** when no cited item says it in those words |
| A "no", "denies" or "without" on one side only: the statement affirms what a cited item denies, or denies what a cited item affirms | **marked** ("may reverse a no") |
| A statement the model calls "stated" that uses words the items it cites do not contain (endings allowed: cough, coughing; the patient line and plain words such as "patient" or numbers in words are not counted) | **marked and shown as inferred** when it has a word of its own; **removed** when it is made mostly of such words. An "inferred" one is marked when at least half its claim words are in no cited item. A summary is looked for in every item shown and one plain word of its own is let through |
| What the cited items say about the thing itself | a **stopped or resolved** item cited by a statement that does not use the past ("is taking"): marked; a **relative's** condition worded as the patient's: marked; "today" or "currently" resting only on **items from an earlier day**: marked "old" |
| An absence ("duration not documented") that a shown item seems to contradict (by its words, or by the thing asked for: a duration, a temperature, a weight…, in an item about the same subject): in a statement the model labels "not found", in every missing-information statement, **and in any sentence of another statement about the record that says something is not recorded** (a summary says "… and the duration of the dizziness is not recorded" beside a reason for the visit that gives it). An item the statement itself cites counts too; an item that itself says the thing is "not recorded" does not | **marked**, the items are added to the sources |
| Diagnosis worded as a fact in a suggestion, the summary, an inferred statement or the lists of what is missing or uncertain (and not in the sources) | **marked** |
| The AI's own **reason** and **uncertainty** for a statement | held to what a suggestion is held to (no link, dose, regimen, diagnosis-as-fact, medicine that is not in the record, or figure that is not in the record); one that breaks a rule is **dropped, not the statement**, and counted |

**Support is decided here, never by the model:** *supported by record* (the cited items say it), *inferred*, *not found*, *conflicting* (the cited items are in a conflict **the fixed rules found**), *outdated* (all cited items older than `mana.outdatedDays`, 180). A conflict the model claims but the rules did not find is only "inferred" and says so. A statement that is marked, or a suggestion that cites nothing, **needs an explicit tick** ("I have checked this against the record") before it can be accepted, and the **server** enforces that. What the checks removed is kept only as **counts by reason** on the draft (the removed text is not stored).

### 2.6 A deterministic record check runs with or without a model

Mana's rules (`record-check-v1`: an allergy and a drafted or current medicine in the same configured group, items older than the configured age, what is not recorded) run on every draft and are shown on their own whenever there is no draft, **including when the model is unavailable**. They are labelled "fixed rules, not AI". A statement that rests on items in a rule-found conflict shows the rule's own sentence beneath it.

### 2.7 Nothing is written without a separate act by the doctor

Generating a draft writes **only** to the draft's own tables. Accept, Edit and Reject record a decision on one statement (append-only; one decision per statement) and **change nothing else**: not the note, not the diagnoses, not the prescription, not the orders. "Add to note" is a second, separate click that uses the existing recorded insertion (provenance, who, when, the exact reviewed text; the text goes at the end of the chosen field and **never replaces what the doctor wrote**). A statement can be added only to a note section, never to the diagnosis list or the prescription: those have no route from a draft.

### 2.8 Every draft is a versioned, auditable record

A draft stores its prompt id, schema version, rules version, validation version, model, runtime, weights SHA-256 (**the pinned file's hash, recorded when the server reports the pinned model alias**: the server does not report a hash of the file it loaded, so this is identity by alias plus the launcher's size-and-hash check of the file before it starts the server, **not a proof about a server someone started by hand with another file under the same alias**; with another alias the hash is left empty), whether it ran locally, the context hash and manifest, the record check, the validation counts, who requested it, and its times; the run (`ai_runs`) stores input and output hashes and token counts; each cited source is an `ai_evidence` row with the excerpt shown to the model. Versions count up per consultation; **older drafts are kept** and only the newest is shown. A finished draft is **immutable and never deleted** (database triggers), and a statement's text never changes (only the doctor's decision is recorded, once). Audit events: `ai.consultation_draft_requested`, `ai.consultation_draft` (the job's outcome, denials, "too little to draft from"), `ai.consultation_draft_cancelled`, `ai.consultation_draft_viewed` (the finished draft reached the doctor's screen: once per doctor and draft, ids and counts only, never a word of it), `ai.consultation_review`, `encounter.ai_insert`.

### 2.9 A draft goes stale; it is not silently refreshed

When the record, the doctor's notes or the confirmed points change after a draft was made, the draft is marked **STALE** with one sentence saying what changed (the manifest is compared with the record as it is now) and each affected statement says "changed since". What the doctor added to the note *from* the draft is not counted as a change. A new draft is the doctor's click; nothing regenerates by itself.

### 2.10 Long, single-slot work is background work

A draft takes **minutes on this CPU** (measured in [safety/AI_MODELS.md](../safety/AI_MODELS.md)). The request returns at once with 202; the work runs in the background through the existing job service; the screen polls, shows elapsed time and a **Cancel** (which stops the model call). One draft per consultation can be generating (a partial unique index), the same idempotency key returns the same draft, a timeout (default 900 s), an unreadable answer or a model that is down end the draft as failed or unavailable with a plain message and a retry, and **drafts left running by a stop are failed at the next start**. **If the patient withdraws consent (or the wording moves on), or the consultation is signed or discarded, while a draft waits its turn or is being made, nothing of the answer is kept:** consent and status are read again after the wait for the model's one slot (so a draft that waited does not send a withdrawn patient's record) and again inside the step that stores the answer; the draft ends CANCELLED with that reason, and the refusal is audited (the audit says whether anything had already been sent to the model).

## 3. Consequences and limits

- **It is slow.** Minutes, not seconds; the screen says so. A faster machine or a GPU build would change this and is not part of V3.
- **Same prompt, same words only on the same machine and build.** With caching off the server's answer does not depend on its history here, but different hardware, a different thread count or another build of the runtime can compute the same prompt slightly differently and a small model's greedy answer can change with it; nothing in V3 claims that a draft can be reproduced elsewhere (what is stored with a draft is what was shown, with the hashes of what produced it).
- **A 4-billion-parameter model is weak.** It misses things and sometimes writes the wrong thing; the checks remove or mark what they can *recognise* (an unknown figure, an invented medicine, a dose, a missing citation, a reversed "no", an absence the record contradicts). **They cannot recognise a wrong statement that is worded plausibly and cites a real source.** That is why every statement is a draft with its sources open to the doctor and why nothing is written automatically.
- **No accuracy is claimed.** [safety/AI_MODELS.md](../safety/AI_MODELS.md) reports counts on 12 synthetic cases written by the authors: whether the drafts were well-formed, grounded, cited, covered what the record plainly says and named what was plainly missing. This is **not clinical validation**; what it says about real patients is nothing.
- **Prompt injection is reduced, not removed.** Record text can contain instructions (a patient's free-text note, a pasted letter). Controls: the model has **no tools, no network and cannot act**; sources are one line each with brackets neutralised so a source cannot pose as another; the task comes after the sources; the output is shape-checked, link-stripped, figure-, dose-, medicine- and citation-checked and **never executed or stored as anything but text for the doctor to read**; considerations cannot carry doses or new medicines. A source can still make the model write a *misleading but cited* sentence; the doctor sees the source beside it.
- **Consent.** V3 uses the existing `ai_recording` consent and its current wording for the local draft. Whether a local model needs a consent of its own, with its own wording, is **a governance question that was not decided here**; the wording changed in V2 and still needs a legal and clinical-governance review.
- **Retention.** Drafts keep the sources' excerpts (the text the model was shown, identifiers replaced) in append-only evidence rows. How long they are kept, and whether withdrawal of consent should remove them, are **governance decisions that are not made**; nothing is purged.
- **The secret and the loopback boundary protect against other machines and web pages, not against another process of the same user.** Anything running as this user can read `.data/llm/api-key` and call the server. The same deployment assumption as the speech service ([ADR 0015](0015-hosted-ai-egress-policy-and-speech-service-hardening.md) §2).
- **English only.** The prompt and the checks assume English text.

## 4. What was not built (and is not claimed)

Streaming text while it is written; automatic regeneration; support for other languages; GPU acceleration; comparison of several models or runtimes; a hosted run of this feature; coding or billing; any route from a draft to the diagnoses, the prescription or an order; patient-facing output; a way for a doctor to correct the AI's *reason* for a statement; learning from decisions (the system does not learn from what doctors accept).

## 5. Where it is tested

`apps/api/test/consult.test.ts` (39 tests, the whole pipeline against a stand-in model: authorisation of the doctor, consent and its withdrawal while a draft waits or is being made, scope of what the model is given, the budget, idempotency, one draft at a time, cancel, timeout, orphaned and interrupted drafts, stale marking, review, insertion limits, other doctors' visibility, the database triggers that keep a finished draft immutable, closed consultations, audit), `consult-validate.test.ts` (53, the checks against answers that invent, reverse a "no", hide words in characters, obey an injected instruction or label themselves to skip a rule), `consult-inputs.test.ts` (6), `consult-eval.test.ts` (11, the scoring of the evaluation), `llm-local.test.ts` (12, the local client against a loopback stand-in: wrong secret, loading, redirects, truncated and malformed answers, timeouts, cancellation), `llm-lock.test.ts` (12, the pinned files, and the launcher **run with `--dry-run`** so that its arguments and the names of the environment it would hand over are checked, not its source text), `egress.test.ts` (local, hosted and none; no fallback; no key to the browser), `e2e/consult.spec.ts` (8 tests in a browser against a labelled stand-in server: the workflow, a conflict, stale, unavailable, failed and cancelled with and without an earlier draft, an injected answer, and every state at five widths with axe), `e2e/consult-real.spec.ts` (opt-in, the real model: the draft in a browser, and the whole chain from recorded speech to the signed record naming the model and prompt), and the evaluation harness (`apps/api/src/eval/consult-cli.ts`, real model, not part of the gate). **Automated tests make no call to a real model or provider**: the API test configuration forces the reasoning provider off, and the end-to-end suite points the API at loopback stand-ins unless the opt-in variable is set.
